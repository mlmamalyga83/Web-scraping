# Глубокий анализ задания и ТЗ — Парсер Habr

## 1. Структура задачи (что требуется по заданию)

**Исходное задание (из docx):**
- Написать парсер для ленты новостей habr.com
- Источник: https://habr.com/ru/feed/ или https://habr.com/ru/articles/
- Пройти по страницам и собрать preview-информацию
- Из preview взять ссылку на полную статью
- Перейти, вытащить полный текст, сверить с ключевыми словами
- Вывод в консоль: дата, название, ссылка
- Список ключевых слов: `['дизайн', 'фото', 'web', 'python']`

**Ключевой момент:** задание чётко разделяет два этапа:
> Этап A — сбор preview-информации на списковой странице  
> Этап B — переход по ссылке, полный текст, проверка ключевых слов

Вывод — ТОЛЬКО для статей, прошедших проверку ключевых слов.

## 2. Несоответствия между текущим ТЗ и заданием/реальностью

### ❌ НЕСООТВЕТСТВИЕ №1: Preview выводится в консоль (ТЗ п.3)

**В ТЗ:** "краткое описание (preview-текст) — оно же выводится в консоль"  
**В задании:** "Вывод в консоль должен содержать дату и название статьи и ссылку."

Preview не выводится! Preview используется ТОЛЬКО как промежуточный шаг — чтобы найти ссылку на полную статью.

**Статус:** Требует исправления в ТЗ.

---

### ❌ НЕСООТВЕТСТВИЕ №2: Нет упоминания User-Agent и заголовков

**В ТЗ:** не сказано про HTTP-заголовки  
**Реальность:** Habr (как и любой современный сайт) проверяет User-Agent. Без него — 403/406/капча.

**Статус:** Требует добавления в ТЗ.

---

### ❌ НЕСООТВЕТСТВИЕ №3: Пагинация никак не описана

**В ТЗ:** ни слова про то, сколько страниц парсить  
**Реальность:** На habr.com 50 страниц статей. Нужно определить лимит.

**Статус:** Требует явного указания (например: "первые N страниц или все, пока есть статьи").

---

### ❌ НЕСООТВЕТСТВИЕ №4: Неверный CSS-путь к полному тексту статьи (ТЗ п.5)

**В ТЗ:** "тег article, внутри блоки <p> или div с классом, содержащим текст"  
**Реальность (после анализа HTML):**

```html
<div class="article-body" id="post-content-body">
  <div>
    <div class="article-formatted-body article-formatted-body_version-2">
      <!-- текст здесь -->
    </div>
  </div>
</div>
```

Селектор для BeautifulSoup: `.article-formatted-body.article-formatted-body_version-2`

**Статус:** Требует уточнения.

---

### ❌ НЕСООТВЕТСТВИЕ №5: Противоречие с источником данных (ТЗ п.2)

**В ТЗ:** только `https://habr.com/ru/articles/`  
**В задании:** альтернатива `https://habr.com/ru/feed/`  
**Реальность:** `/ru/feed/` — это лента (feed), там другая вёрстка. `/ru/articles/` — это страница со списком всех статей.

Нужно выбрать один источник и обосновать.

**Статус:** Требует либо явного выбора `/ru/articles/` с обоснованием, либо поддержки обоих.

---

### ❌ НЕСООТВЕТСТВИЕ №6: Формат даты не указан (ТЗ п.6)

**В ТЗ:** в примере `2025-06-15`  
**Реальность:** в HTML дата в формате `datetime="2026-11-26T09:02:05.000Z"` (ISO 8601)

Нужно указать: берём из атрибута `datetime` у тега `<time>`, форматируем в `ГГГГ-ММ-ДД`.

**Статус:** Требует уточнения.

---

### ⚠️ ЗАМЕЧАНИЕ №7: Зависимость от версии HTML-структуры

Сайт использует Vue.js + SSR. CSS-классы вида `article-formatted-body_version-2` говорят о том, что есть версионирование. Если habr обновит шаблон, класс может измениться на `_version-3`.

**Риск:** низкий (структура стабильна), но стоит указать как потенциальную точку отказа.

**Статус:** Информационно, можно добавить примечание.

---

### ⚠️ ЗАМЕЧАНИЕ №8: Selenium не нужен

Задание НЕ требует динамического парсинга JavaScript. SSR отдаёт готовый HTML.  
requests + BeautifulSoup достаточно.

**Это хорошо.** Не нужно усложнять решение Selenium'ом.

**Статус:** Информационно.

---

### ⚠️ ЗАМЕЧАНИЕ №9: Капча и блокировки

При частых запросах habr может показать капчу.  
time.sleep(1) может быть недостаточно при 50 страницах × 20 статей = 1000 запросов.

**Рекомендация:** парсить первые 1-2 страницы (40-80 статей) для демонстрации работы.

**Статус:** Требует явного указания лимита страниц.

## 3. Корректировка ТЗ

С учётом всех несостыковок, предлагаю следующую **финальную версию требований**:

| Параметр | Значение |
|---|---|
| **Источник данных** | `https://habr.com/ru/articles/` (явный выбор) |
| **Что собираем в preview** | заголовок, дата, ссылка на полную статью |
| **Вывод в консоль** | только `дата | заголовок | ссылка` (для статей, где найдены ключевые слова) |
| **Ключевые слова** | `['дизайн', 'фото', 'web', 'python']` |
| **Проверка** | регистронезависимая, полный текст статьи |
| **Пагинация** | страницы 1..N, пока есть下一页 (но не более 2 страниц для демо) |
| **HTTP** | заголовки: User-Agent, Accept-Language |
| **Задержка** | 1 секунда между запросами |
| **Формат даты** | из `datetime` атрибута, вывод в `YYYY-MM-DD` |
| **Библиотеки** | requests, beautifulsoup4 |
| **Лимит** | 2 страницы списка (чтобы не нагружать сайт) |

## 4. Детальный архитектурный план

### 4.1. Общая архитектура

```
main()
  │
  ├─ PARSE_ARTICLES_LIST(url)
  │     Отдаёт список статей на странице
  │     Возвращает: [{'title', 'date', 'link'}, ...]
  │
  ├─ PROCESS_ARTICLE(url)
  │     Переходит по ссылке статьи
  │     Возвращает: полный текст (str)
  │
  ├─ CHECK_KEYWORDS(text, keywords)
  │     Проверяет текст на ключевые слова
  │     Возвращает: True/False
  │
  └─ Форматирование и вывод
```

### 4.2. Детализация функций

#### `fetch_page(url) -> str | None`
- Принимает URL
- Отправляет GET-запрос с заголовками (User-Agent, Accept-Language)
- Проверяет status_code == 200
- При ошибке: print("[WARN] ... ") и return None
- **Зависимости:** requests

#### `parse_articles_list(html: str) -> list[dict]`
- Принимает HTML страницы со списком статей
- Создаёт BeautifulSoup-объект
- Находит все `<article class="tm-articles-list__item">` через `soup.find_all('article', class_='tm-articles-list__item')`
- Для каждого article:
  - **Заголовок:** `article.find('h2').find('a.tm-title__link').find('span').get_text(strip=True)` — через цепочку find
  - **Ссылка:** `article.find('a.tm-title__link')['href']` — относительная, нужно сформировать полный URL через `urljoin('https://habr.com', href)`
  - **Дата:** `article.find('time')['datetime']` — строка вида `2026-11-26T09:02:05.000Z`
    - Парсим через `datetime.fromisoformat(...)` (в Python 3.11+)
    - Или через `datetime.strptime(...)` для совместимости
  - Форматируем дату в `YYYY-MM-DD`
- Возвращает список словарей
- **Зависимости:** beautifulsoup4, datetime

#### `parse_full_text(html: str) -> str | None`
- Принимает HTML страницы статьи
- Находит `soup.select_one('.article-formatted-body.article-formatted-body_version-2')`
- Извлекает текст: `.get_text(strip=True)` — вся текстовая информация внутри блока
- Возвращает строку
- Если блок не найден — return None
- **Зависимости:** beautifulsoup4

#### `check_keywords(text: str, keywords: list[str]) -> bool`
- Принимает текст (str) и список ключевых слов (list[str])
- Приводит текст к нижнему регистру: `text.lower()`
- Для каждого keyword: проверяет `keyword.lower() in text_lower`
- Если хотя бы одно найдено — return True
- **Примечание:** оператор `in` в Python проверяет подстроку, а не whole word. 
  Например, "python" будет найдено в "pythonic" — **это поведение может быть как 
  желательным, так и нет**. Для учебного задания — приемлемо.
  - Альтернатива: разбить текст на слова и проверять intersection множеств.
  - **Решение:** используем `in` (проще), но в коде можно оставить комментарий про 
    потенциальное улучшение.

#### `main()`
- Определяет `BASE_URL = 'https://habr.com'`
- Определяет `ARTICLES_URL = 'https://habr.com/ru/articles/'`
- Определяет `KEYWORDS = ['дизайн', 'фото', 'web', 'python']`
- Определяет `MAX_PAGES = 2` (лимит страниц для парсинга)
- Цикл по страницам 1..MAX_PAGES:
  - Для page=1: URL = ARTICLES_URL
  - Для page>1: URL = f'{ARTICLES_URL}page{page}/'
  - fetch_page(url) → html
  - parse_articles_list(html) → articles
  - Для каждой статьи:
    - Формируем полный URL: `urljoin(BASE_URL, article['link'])`
    - fetch_page(full_url) → article_html
    - parse_full_text(article_html) → text
    - если text is None — пропускаем
    - check_keywords(text, KEYWORDS) → matched
    - если matched — выводим в консоль
  - Пауза 1 секунда

### 4.3. Потенциальные проблемы и их решение

| Проблема | Решение |
|---|---|
| Habr возвращает 403/429 | Добавить User-Agent и Accept; увеличить задержку |
| Пустой список статей | Проверить селекторы; вывести предупреждение |
| Длинный вывод (>200 статей) | Лимит 2 страницы (~40 статей) |
| Разные URL для корпоративных статей | urljoin обработает любые относительные ссылки |
| Дата отсутствует | Пропустить статью с предупреждением |

### 4.4. Формат вывода (пример реальный)

```
2026-11-26 | Торвальдс: Скажите своему ИИ‑помощнику, чтобы он взялся за ум | https://habr.com/ru/articles/1112210/
2026-11-25 | Обзор PyCharm 2025.3 | https://habr.com/ru/articles/1112189/
Совпадений не найдено.
```

### Шаг 2. Создание файла `parser.py`

### Шаг 3. Реализация `fetch_page()`
- headers = {'User-Agent': '...', 'Accept-Language': 'ru-RU'}
- response = requests.get(url, headers=headers)
- response.raise_for_status()
- return response.text

### Шаг 4. Реализация `parse_articles_list()`
- soup = BeautifulSoup(html, 'lxml')  # или 'html.parser'
- articles = soup.find_all('article', class_='tm-articles-list__item')
- Цикл по articles:
  - Извлечь title, date_str, link
  - Преобразовать date_str → datetime → YYYY-MM-DD
  - Добавить в список

### Шаг 5. Реализация `parse_full_text()`
- soup = BeautifulSoup(html, 'lxml')
- body = soup.select_one('.article-formatted-body.article-formatted-body_version-2')
- if body: return body.get_text(strip=True)

### Шаг 6. Реализация `check_keywords()`
- text_lower = text.lower()
- any(kw.lower() in text_lower for kw in keywords)

### Шаг 7. Реализация `main()`
- Склеить всё.
- Добавить счётчик найденных статей.
- Если счётчик == 0 → "Совпадений не найдено".
